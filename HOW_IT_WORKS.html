Bean-Hoarder v2

작동 방식

구글시트 대신 Cloudflare D1(데이터베이스)과 Pages Functions(서버 코드)로 처음부터 다시 설계한 버전. "웹에 게시" 같은 수동 단계 없이, 가입하면 바로 등록하고 조회할 수 있다.

비용 0원 Cloudflare Pages 프로젝트 1개 D1 (SQLite) Pages Functions 백엔드 서버 없음

01 · 전체 구조

한 프로젝트 안에 정적 페이지, API, DB가 모두 있다

v1은 조회 웹앱(Cloudflare Pages) · 원두 DB(구글시트) · 라벨 도구(로컬 파이썬)가 서로 다른 세 곳에 흩어져 있었다. v2는 이 세 가지를 하나의 Cloudflare Pages 프로젝트 안으로 합쳤다 — 정적 파일과 서버 코드(Functions)와 데이터베이스(D1)가 같은 배포 단위에 있어서, 저장소를 git push 하나로 셋 다 함께 배포된다.

02 · 흐름 1

가입 — 초대코드와 4자리 암호만으로 계정이 생긴다

이 서비스는 여러 로스터리에서 원두를 사 모으는 "원두 호더" 개인용이다. 그래서 가입에 로스터리명이 필요 없다 — 초대코드와 내가 쓸 숫자 4자리 암호만 정하면 서버가 유저코드를 발급한다. 암호는 탈취돼도 무방한 편의용(무단 등록·수정 방지 수준)이고, 유저코드+암호만 기억하면 어느 기기에서든 로그인된다.

1
초대코드 + 암호운영자가 공유한 코드, 내가 정한 숫자 4자리
→
2
POST /api/signupFunctions가 초대코드·암호 형식 검증
→
3
유저코드 발급무작위 4자리, 암호는 해시로만 저장
→
4
브라우저 저장세션 토큰을 브라우저에 저장, 재방문 시 자동 로그인

03 · 흐름 2

원두 등록 — 서버가 KEY를 채번하고 QR을 자동 검증한다

폼을 채우는 동안 라벨은 "예상 KEY"로 실시간 미리보기된다. 실제 저장은 등록 버튼을 눌렀을 때 한 번, 서버 쪽에서 일어난다 — 같은 연도·같은 유저코드 안에서 원자적으로 다음 번호를 배정하므로 두 사람이 동시에 등록해도 번호가 겹치지 않는다.

1
폼 입력입력할 때마다 라벨 미리보기 갱신
→
2
POST /api/beans세션 토큰으로 인증된 요청
→
3
서버가 KEY 채번같은 유저코드·연도 내 최대값+1
→
4
QR 자동 검증203dpi로 래스터화 후 jsQR로 실제 디코드
→
5
URL·QR 복사상세 URL 또는 QR 이미지를 클립보드로. 라벨 PNG 다운로드는 선택

등록 후에는 "내 원두 목록"에서 언제든 수정(PUT)·삭제(DELETE)할 수 있다 — KEY 앞 4자리가 내 유저코드인 원두만 건드릴 수 있다.

04 · 흐름 3

QR 스캔 → 조회 — 데이터베이스를 직접 읽어 렌더링

라벨의 QR은 https://bnhd.pages.dev/{KEY} 를 가리킨다. v1처럼 CSV를 통째로 내려받아 클라이언트에서 찾는 대신, 서버가 그 KEY 한 건만 조회해서 돌려준다.

1
QR 스캔폰 카메라가 라벨의 QR을 인식
→
2
페이지 접속/{KEY} 경로로 이동
→
3
GET /api/bean/{KEY}D1에서 해당 행 한 건만 조회
→
4
카드 렌더링원산지·가공·로스팅일 표시, 빈 필드는 자동 숨김

06 · 보안 모델

무료 범위 안에서 최소한으로 충분하게

  • 가입: 초대코드(운영자가 공유) + 숫자 4자리 암호만으로 계정 생성. 초대코드는 Cloudflare secret으로 관리 — 저장소에 없고 언제든 교체 가능.
  • 암호: 탈취돼도 무방한 편의용 — 무단 등록·수정을 막는 수준. 서버는 PBKDF2(유저코드:암호) 해시만 저장.
  • 복구키: 가입 시 1회 표시되는 고엔트로피 키. 유저코드·암호를 모두 잊었을 때의 유일한 복구 수단이며 사용하면 회전된다.
  • 무차별 대입: 4자리 암호 특성상 D1 기반 rate limit으로 차단 — 유저코드당 10회/10분, IP당 30회/10분 초과 시 429.
  • 쓰기: 등록·수정·삭제·백업에 세션 토큰(POST /api/login으로 발급, 90일 만료)이 필요 — Authorization: Bearer 헤더로 전송한다. 브라우저는 암호가 아니라 토큰만 저장한다(레거시 유저코드:암호 헤더도 이행기 동안 동작).
  • 읽기: 완전 공개 — QR 스캔이 목적이므로 조회에는 인증이 없다.
  • 소유권: 수정·삭제는 KEY 앞 4자리 = 내 유저코드인 원두만 가능.
  • 데이터 회복: CSV 백업을 언제든 내려받고, 같은 파일로 복원(같은 KEY 덮어쓰기) — 실수·악의적 변조를 백업 시점으로 되돌린다.
  • 오남용 대응: 운영자가 D1에서 해당 사용자 행을 삭제하면 즉시 차단.
